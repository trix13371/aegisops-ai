# Приёмка S0-02: контракты и синтетический источник

14 октября 2026. Реализована S0-02 из части B технического документа Stage −1,
редакция 2.1. Код сохранён в том же отдельном Git-проекте, что S0-01.

## Готово

- 24 frozen Pydantic DTO/схемы: наблюдения, evidence, диагнозы и drafts,
  рекомендации, политика, dry-run, AuditRecord, каталог и описание сценария.
- Ограничения длины/размера, UTC, strict числа/boolean, запрет extra fields,
  неизвестных origin/action/уровней. Лог ограничен и по UTF-8 байтам, и по строкам.
- Application binding задаёт ID, класс обратимости из каталога, human approval
  и execution_performed=False; вывод модели не может задавать эти поля.
- Диагноз связывается только с известными evidence инцидента; AuditRecord
  повторно проверяет ссылки между частями, статусы, время и хеш контекста.
- Версионированный каталог четырёх действий с default rejection плохих параметров.
  Каталог описывает действия, но не реализует их.
- 10 вручную созданных сценариев: 4 позитивных, 4 негативных, 2 safety.
- `aegisops scenario list/show`: без БД, Kubernetes и LLM; сырые логи скрыты.
- JSON Schema и эталонный JSON на каждый из 24 контрактов, проверка stale exports.
- Assets входят в wheel; их копии проверяются против канонических входов.

## Проверки

Полный локальный прогон: **97 passed, 1 skipped**. Единственный пропуск —
создание настоящего symlink в Windows без соответствующего права. Traversal,
containment и отказ на промежуточный symlink проверены; для последнего есть
отдельный тест с контролируемым Path.is_symlink. Реальная Linux-проверка
будет выполнена при запуске CI; удалённый workflow пока не запускался.

Ruff lint/format, mypy strict (17 файлов), import-linter, экспорт схем и
сверка assets прошли. Сохранены проверки PostgreSQL из S0-01. pip-audit:
74 зависимости, 0 известных уязвимостей. Gitleaks запускается pre-commit и
проверяет подготовленные файлы; секреты проекта исключены из Git.

Wheel установлен в отдельное чистое окружение: все 10 сценариев загружены,
каталог содержит 4 действия, registry экспортирует 24 схемы. После исправления
UTF-8 вывода CLI повторно прошли 26 профильных тестов (1 symlink skip);
типизация проверена снова. Пакет пересобран с этим исправлением.

JSON Schema проверяет структуру и скалярные ограничения. Ссылки evidence,
согласованность между частями, Unicode byte limits и другие relational rules
проверяет Python runtime. Структурный Diagnosis сам по себе не связывает
evidence: на входной границе обязательно bind_diagnosis/validate_diagnosis.
Проверяется совпадение предоставленных context_hash, но вычисление хеша из
санитизированного контекста выполняет будущий ContextBuilder. Это не подпись
или свидетельство подлинности данных.

## Реальные ошибки и ревью

DeepSeek написал модели и загрузчики. Первая версия загрузчиков неверно
вызвала общий containment helper и не прошла mypy; модель исправила её после
обратной связи с точной сигнатурой. Оркестратор исправил ещё три дефекта:
101 строка без завершающего newline проходила лимит 100; context_hash мог
отсутствовать в готовой записи; True принимался как версия схемы 1.

Gemini написал независимые отрицательные тесты. Первая версия использовала
несуществующие интерфейсы и не прошла collection. После повторного задания
имена исправлены. Оркестратор дополнительно устранил ложные проверки:
ошибку индекса пустого events, широкие pytest.raises(Exception), невалидный
seed и тест model_construct на поле, которое сам Pydantic уже отбросил.
Сохранены проверки на реально неверные params и обход обычной валидации.
Результат модели не принимался без запуска и чтения тестов.

Финальное ревью Gemini содержало три замечания:

1. «JSON dump ломает datetime при binding» — не подтвердилось: drafts не
   содержат datetime, а Pydantic принимает ISO UTC. Дополнительно проверены
   validated model instances и полный JSON round-trip AuditRecord.
2. «Evidence контекста должен быть полностью равен сырому evidence» —
   отклонено: план предусматривает санитизированный контекст. IDs обязаны
   совпадать, summary/attributes могут быть очищены. Есть позитивный тест.
3. Промежуточный symlink и нестрогое разрешение пути — исправлено:
   проверяются компоненты, абсолютные пути и traversal, resolve(strict=True).

Оркестратор также подготовил common types, binding, файлы сценариев,
экспорт/эталоны, тесты связей/файлов/схем, CLI и документацию. Readonly mapping
защищает от обычной мутации, но не от произвольного враждебного Python-кода.

## Граница этапа

Не реализованы detector, sanitizer, LLM-адаптер, PolicyChecker/DryRunEngine,
AuditStore или Kubernetes adapter. Fixtures созданы вручную, не сняты с
кластера и не подтверждают качество модели. Рекомендации не исполняются.
Следующая задача S0-03 — kind, reader RBAC, отдельный kubeconfig и сценарии.

Основание: [Pydantic validators](https://docs.pydantic.dev/latest/concepts/validators/),
[JSON Schema export](https://docs.pydantic.dev/latest/concepts/json_schema/).
