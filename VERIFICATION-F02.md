# F02 — обратная связь по рекомендациям

15 октября 2026. Минимальный интерфейс оценки из п. 4.5 Foundation & Safety.
Добавлены `feedback add/list/summary`, чистые DTO, санитизация комментариев и
отдельная таблица `recommendation_feedback`. Миграция `0002_feedback` применена
в локальной PostgreSQL; прежние audit_runs не изменяются.

Оценки useful/incorrect/unsafe/uncertain привязаны к сохранённой рекомендации
по run UUID, recommendation ID/hash и origin. У запуска без рекомендации
оценить нечего — запись отвергается. Reviewer является локальным псевдонимом,
не подтверждённой SRE identity. Комментарии ограничены и очищаются до INSERT
и при чтении. Вывод add появляется только после COMMIT.

Исправление создаёт новую запись с явным supersedes_id. Уникальные индексы
обеспечивают один корень и одного преемника; составной FK запрещает чужой
run/reviewer. Старый parent или конкурирующая правка отвергаются без потери
истории. У app-роли только SELECT/INSERT; doctor контролирует обе таблицы.

Сводка считает только текущие листья, отдельно для synthetic/local-kind,
с лимитом 1…100, sample_size и has_more. Это число мнений, не независимых
инцидентов и не accuracy. В локальной разработческой БД есть отзывы тестов;
они не являются фактическими оценками SRE. Golden-набор постмортемов,
подтверждённые исходы инцидентов и gate G0 в этот срез не входят.

Проверено:

- Полный pytest с PostgreSQL и `AEGISOPS_KIND_LIVE=1`: **546 passed,
  1 skipped, 2 deselected**, включая 20 живых kind-тестов. Пропущен Windows
  symlink; два платных API-теста исключены по умолчанию.
- 53 новых unit/integration/safety-кейса: типы и размеры, отсутствие полей
  исполнения, редактирование комментария, канонический hash, неизвестный run,
  отсутствие рекомендации, история исправлений, чужой/старый parent, bounded
  summary и разделение origin, две реальные гонки записи в PostgreSQL,
  SQL constraints, UPDATE/DELETE/TRUNCATE/DDL запреты и обнаружение лишних прав.
- CLI возвращает только сохранённый отзыв; отказ хранения не выдаёт успешный
  record, ошибки и недопустимые URL не раскрывают содержимое/credentials.
- Пример run → useful → исправление uncertain → чтение истории и исходного
  аудита выполнен автоматически. [Безопасная сводка](docs/verification/f02-feedback/summary.json)
  явно помечает пример как автоматический, а не оценку SRE.
- Ruff/format, mypy (55 файлов), 7 контрактов import-linter, 31 экспортированная
  JSON Schema с golden-примерами, package assets, Alembic check и doctor
  local-kind прошли. SQLAlchemy metadata соответствует реальной схеме.
- Pre-commit и gitleaks staged прошли без находок секретов.

DeepSeek подготовил DTO и чистую валидацию; Gemini независимо просмотрел
хранение/миграцию. Предположения ревью о подсчёте листьев проверены настоящими
PostgreSQL-тестами; ветвления не допускаются ограничениями БД. Код проверялся
перед применением. Телеметрия и отзывы моделям не отправлялись, платного
анализа инцидентов в приёмке нет. Удалённый CI не запускался.

Это локальный механизм обратной связи уровня L0. Нет аутентификации SRE,
подписи/WORM, автоматического изменения политик или обучения модели по оценкам.
Свободный текст очищается эвристически; shell history не контролируется.
Решение: [ADR-011](docs/decisions/ADR-011-human-feedback.md).
