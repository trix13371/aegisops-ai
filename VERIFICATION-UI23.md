# UI23: оценка качества разбора на Python, JavaScript и TypeScript

19 октября 2026. Решение: [ADR-039](docs/decisions/ADR-039-versioned-code-evaluation.md).

## Что добавлено

- Отдельный набор v2 из 9 фиксированных примеров: по 3 на язык; 5 случаев
  с дефектом, 2 чистых, 2 с инъекцией в корректном коде; 2 многофайловых случая.
- Сопоставление по файлу, строкам и категории с максимальным паросочетанием;
  дубли замечаний не дают лишний TP. Строгая проверка цитат сохранена.
- Покрытие, TP/FP/FN, precision/recall, языковые сводки, ложные срабатывания,
  счётчики токенов принятых ответов. Частичный результат не получает итоговых
  precision/recall, но сохраняет доступные счётчики и ограничения.
- Хеш и профиль сохранены в claim; классы результатов выбираются по claim.
  Старый набор v1, API, согласие на 3 запроса и чтение старых отчётов сохранены.
- Новое согласие v2: максимум 9 запросов и 25200 выходных токенов; стоимость
  зависит от сервиса. Выбранная модель и провайдер фиксируются прежней привязкой.
  При первой ошибке выполнение прекращается без автоматического повтора.

## Выполненные проверки

- Общая регрессия с PostgreSQL: **1582 passed, 4 skipped, 69 deselected**,
  178.30 s. Integration/E2E включены. Live LLM/kind/OPA/runner исключены;
  четыре пропуска не засчитываются как проверенные сценарии.
- Целевой новый Python-набор: **21 passed**. Состав, хеш, отсутствие меток
  в wire payload, идеальные/пустые/частичные синтетические ответы, неверный файл,
  дубли и максимальное сопоставление, строгие диапазоны/usage/report,
  смешанная история, устаревший claim без профиля, повреждённое хранение,
  остановка worker при ошибке, предел запросов, запрет повторного выполнения,
  v1 ровно 3 вызова и v2 ровно 9 — на подменённом транспорте.
- HTTP: Host/сессия, GET без создания claim, точное согласие, запрет лишних
  полей, фиксация модели и общая блокировка v1/v2. Входящие маршруты новые;
  новая схема endpoint/model произвольно из запроса не принимается.
- UI MockDOM: **53 passed**. Явное согласие, повреждённый каталог, запоздалый
  ответ после закрытия, блокировка после неопределённого POST; завершённый
  и частичный v2, числовое покрытие языка, токены, исходный legacy-отчёт,
  буквальное отображение HTML-подобного текста. Это проверка представления,
  не подтверждение реального качества модели.
- Ruff lint/format, mypy (**149 source files**), import-linter
  (**25 contracts**), node --check — успешно.
- **57 schemas** и package assets проверены. Wheel/sdist собираются offline;
  5 изменённых файлов пакета сверены с wheel, host и worker — с sdist.
- Gitleaks staged: **no leaks found**. Правила и исключения не расширялись.

Общий Python-прогон выполнен на итоговом Python-коде. Последующие уточнения

## Настоящий HTTP и браузер

Приложение штатно перезапущено. Авторизованные GET v1 и v2 вернули HTTP 200,
соответственно 3 и 9 примеров. Два builder хеша v2 дают одинаковый SHA-256;
изменённый набор старого профиля не подменяется новым. Каталог v2 сохранён
локально без истории и credentials: `.local/ui23-catalog.json`.

В браузере открыто «Выбрать проверку → Оценка качества AI». Видны 9 примеров,
3 языка, лимит 9 запросов / 25200 выходных токенов, предварительные метки,
свернутые исходники и существующий legacy-отчёт. Согласие не отмечено,
«Запустить оценку» отключена. Скриншот: `.local/ui23-evaluation.png`.
Открытие и чтение не вызвали runtime-модель и не создали новую оценку.

## Авторство и границы

Продуктовый код подготовлен DeepSeek через API разработки; тесты и независимое
ревью — Gemini. Оркестратор применял проверенные ответы, выполнял команды,
проверял результат и писал документацию. Усечённые ответы не применялись.
Ошибки сигнатур, фикстур, UI-категорий, диапазона строк и отображения полей
возвращались авторам; все применённые проверки затем выполнены реально.
Предположение первого ревью о разных хешах опровергнуто исполнением и снято
автором. Итоговые ревью ядра и представления: pass, findings=[];
независимое ревью фикстур также pass.

**Платных runtime-вызовов при приёмке нет.** Синтетические ответы проверяют
алгоритм, не точность настоящей модели. Метки остаются предварительными:
ручная разметка человеком и большой репрезентативный benchmark не выполнены.
Инъекции оцениваются по отсутствию ложных находок в этих примерах; это не
доказательство полной устойчивости к prompt injection. Токены относятся к
принятым ответам; невалидный/оборванный вызов тоже может быть платным и не
попасть в эти счётчики. Цены и расход в долларах не обещаются.

Runtime-ключи, credentials и выбранная модель не менялись. Секреты, .env,
пользовательские папки и runtime-логи моделям разработки не отправлялись.
Код примеров не запускался приложением. Live runner/kind/OPA, удалённый CI,
чистая установка ОС и публичный хостинг повторно не принимались.
Публикация в GitHub не выполнялась.
