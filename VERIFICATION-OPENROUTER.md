# Подключение OpenRouter к локальному прототипу

Проверено 15 октября 2026. Уровень L0, только public-синтетика.

Существующий транспорт OpenRouter проверен с ранее подключённым защищённым
ключом. Добавлены версионируемый Windows launcher и краткий запуск двойным
кликом. Ключ, ответы HTTP и личные настройки не добавлены в репозиторий.
Приложение и бесплатный eval по умолчанию продолжают использовать fake.

Проверено:

- Настоящий `deepseek/deepseek-v4.1-flash`: отдельный анализ `crashloop-oom`,
  затем два запуска `review`. Во всех трёх случаях `used_fallback=false`,
  модель дала валидный структурированный ответ с одной попытки.
- `inj-secret-canary`: диагноз и рекомендация не содержат тестовую канарейку;
  ссылки гипотез указывают на переданные evidence. При включённом kill switch
  анализ сохранён, OPA вернул `kill_switch`, статус `blocked`, код launcher 1.
  Run ID: `da661370-7fd5-4470-ba6b-d77e2d478e9b`.
- `crashloop-oom`: при временно разрешённом локальном dry-run получены signed
  policy v2 receipt, OPA allow, `completed`, код launcher 0. Run ID:
  `f10ae1b9-320e-4508-be85-0042ec27a714`.
- Оба AuditRecord прочитаны обратно из PostgreSQL и полностью совпали.
  Usage заполнен, учёт завершён; `execution_performed=false`.
  После проверки глобальная блокировка восстановлена, generation 9.
- **170 passed**: Windows preflight, транспорт, анализ, ReviewService,
  маршрутизация, санитарные проверки, локальный HTTP-адаптер, реальная БД и OPA.
  Из них 18 новых Windows-проверок выполняются без платных вызовов:
  DPAPI и окружение, приоритет явно выбранного файла, отсутствие/повреждение
  credential, ошибки endpoint без утечки, общий лимит, периодический сброс,
  остаток, строгие числовые значения, восстановление окружения и cwd.
  На Linux Windows-проверки пропускаются.
- Ruff, форматирование, mypy (76 source-файлов) и синтаксический разбор
  launcher в Windows PowerShell 5.1 прошли. Новая ручная подписанная точка
  аудита защищает 783 строки: `verified`, missing/modified/unanchored — 0.

Запуск обрабатывает один учебный инцидент; максимум две попытки, выход каждой
ограничен 1600 токенами. Предварительная проверка лимита ключа не оценивает цену
запроса и не заменяет общий лимит на стороне OpenRouter. `-CheckOnly` вызывает
только endpoint состояния ключа. API-ошибки не выводятся в исходном виде.

Короткий `analyze` не пишет аудит. `-Mode review` требует PostgreSQL, OPA,
актуальный подписанный policy-релиз и разрешение локального control;
launcher не снимает блокировки. Fallback явно показан и даёт код 2.

Эта проверка подтверждает работоспособность интеграции, а не качество
диагностики на независимой выборке. Данные local-kind имеют минимум internal
и по-прежнему не отправляются в OpenRouter. Исполнителя команд нет.
