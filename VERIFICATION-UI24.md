# UI24: первый реальный прогон и диагностика сбоев

19 октября 2026. Решение: [ADR-040](docs/decisions/ADR-040-safe-evaluation-failures.md).

## Реальный прогон

Пользователь разрешил один контрольный запуск до 9 платных запросов. Перед ним
по исходникам сверены все девять ожиданий:
[сверка](docs/verification/ui24/gold-inspection.md). Это проверка оркестратором,
не независимая человеческая разметка; метки остаются предварительными.
Набор и SHA-256 не менялись до или после запуска.

Через интерфейс отмечено согласие v2 и один раз нажата «Запустить оценку».
Подключённая модель: deepseek/deepseek-v4.1-flash. Сохранён результат
`8c994c21-36b2-4142-b7e2-3a2931b9910f` с profile synthetic-file-overlap-v2,
status failed, **0 из 9 принятых ответов**, complete=false, precision/recall=null.
Выполнение остановилось на первой попытке, последующие восемь не выполнялись.
От создания claim до результата прошло приблизительно 31.5 секунды.

Это похоже на ограничение транспорта 30 секунд, но точная причина тогда не
сохранялась: **тайм-аут не подтверждён**. Неизвестны фактическое списание,
провайдерский finish reason и был ли получен невалидный ответ. Пустые usage/answers
не доказывают бесплатность попытки. Второй платный запуск не выполнялся;
текущая оценка качества модели не получена. Инструкции модели по несуществующим
ответам не перенастраивались.

Отдельная проверка сети без ключа и без запроса к модели: HTTPS HEAD к сайту
провайдера дал HTTP 200 за 0.50 секунды. Это доказывает доступность сайта в момент
проверки, но не успех авторизованного inference и не причину предыдущего сбоя.

## Что исправлено

- AnalysisError сохраняет закрытый безопасный код вместо потери причины.
- OpenRouter-транспорт различает timeout/network/http_error/invalid_response;
  некорректный CodeReview отмечается invalid_review. Неизвестная причина — unavailable.
- V2 сохраняет необязательные failure.code и failure.case_id; принятые ответы
  и usage остаются. Завершённый результат с failure и неизвестные коды/примеры
  отвергаются. V1 DTO и старые V2 без failure совместимы.
- Интерфейс показывает локальные подписи, текущий пример и отсутствие retry;
  старый результат честно остаётся с неизвестной причиной.
- Токены подписаны как расход принятых ответов; для частичного результата
  явно указана неизвестность расхода неуспешного запроса.

Ключи, выбранная модель, провайдер и контракты доставки не менялись. Deadline,
TLS, byte/output budgets и отсутствие fallback/retry сохранены. Исходная failed
запись не перезаписана: в её JSON по-прежнему нет поля failure, а новый DTO читает
его как None. Хеш claim по-прежнему совпадает с неизменённым набором.

## Реально выполненные проверки

- Общая регрессия с PostgreSQL: **1593 passed, 4 skipped, 69 deselected**,
  186.06 s. Live LLM/kind/OPA/runner исключены; integration/E2E включены.
- Новый Python-набор диагностики и весь V2 worker: **16 passed**. Новых тестов
  11: 9 транспорта/DTO и 2 worker. Проверены тайм-ауты соединения, ответа и чтения,
  OSError до/после deadline, HTTP/Content-Length, JSON/finish/tools/usage,
  одна попытка и очистка соединения/таймера, канарейки, сохранение двух принятых
  ответов перед третьей ошибкой, неизвестный изменённый код и совместимость DTO.
- Прежний целевой набор транспорта/выбранного кода/V2 до новых тестов:
  **65 passed, 1 skipped**. Пропуск не считается приёмкой сценария ОС.
- UI MockDOM: **56 passed**, включая 3 новых сценария timeout, старого failed
  без failure и неизвестного HTML-подобного кода; проверки согласия не условные.
  Уточнение подписи токенов и её тесты выполнены после общего Python-прогона;
  полный UI-набор повторён после этого уточнения.
- Ruff lint/format, mypy **149 source files**, import-linter **25 contracts**,
  node --check, **57 schemas**, package assets — успешно.
- Wheel/sdist собраны offline; 4 Python/JS файла пакета сверены побайтно,
  worker — с sdist. Gitleaks staged: no leaks found, без новых исключений.
- Независимое статическое ревью Gemini: pass, findings=[]. Сетевой прогон
  ревьюер не исполнял. Продуктовый код — DeepSeek, тесты — Gemini;
  оркестратор применял ответы, выполнял проверки и писал документацию.

Исходные кандидаты с неверными сигнатурами, ошибочным временем в тесте, условной
проверкой отсутствующего checkbox и выдуманным свойством DOM исправлены автором.
Усечённые ответы не применялись. Ключи/.env/DPAPI, пользовательский код и runtime-логи
в задания разработки не отправлялись; передавались исходники и краткий факт сбоя.

## Настоящий браузер и артефакты

Приложение штатно перезапущено. В истории видно failed, 0 из 9, отсутствие
итоговых метрик, неизвестную причину и прежний отчёт v1. Новый запуск не выполнялся:
согласие пустое, кнопка запуска отключена. Проверена новая подпись токенов.

Локально вне Git: `.local/ui24-baseline-result.json`,
`.local/ui24-regression-final.xml`, `.local/ui24-evaluation-result.png`,
`.local/ui24-dist/`. В Git — исходники приложения, документация и тесты;
машинная сводка: [summary.json](docs/verification/ui24/summary.json).

Главное ограничение остаётся: **качество настоящей модели пока не измерено**.
Для продолжения нужен новый отдельно разрешённый прогон с новой диагностикой.
Он тоже может быть платным. Публичный хостинг, удалённый CI, live runner/kind/OPA
и чистая установка ОС этим шагом не принимались. GitHub push не выполнялся.
