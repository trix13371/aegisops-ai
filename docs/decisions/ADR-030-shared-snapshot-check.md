# ADR-030: совместная проверка файлов и тестов по одному снимку

Статус: принято. Дата: 17 октября 2026.

Историческая сводка UI10 объединяет независимо выполненные проверки. У старого
статического отчёта нет хеша исходников, поэтому общую версию файлов подтвердить
невозможно. Старые DTO, их сериализация, хеши и предупреждения сохраняются.

Добавлен отдельный запуск `project_full_check` с согласием
`project-full-check-v1`, зарегистрированным UUID проекта и одним из существующих
окружений. Общий lock dashboard разрешает только одну активную работу. Новые GET
читают историю и результат, используя прежние session/Host/Origin/CSP ограничения.
Новых сетевых интерфейсов или команд исполнения у приложения нет.

Доверенный оператор `scripts/project-check-local.py` фиксирует отдельный O_EXCL
маркер, вызывает `snapshot_project` ровно один раз, проверяет архив и выполняет
статический анализ его файлов в новой временной папке. Разрешены только обычные
файлы с ограничениями размера, глубины и количества; ссылки, опасные Windows-пути,
приватные имена, дубли и коллизии регистра/префиксов отклоняются. `extractall` не
используется. Тот же объект Snapshot передаётся внутренней функции `run_check`.
Через CLI и HTTP передать готовый архив нельзя. Docker hardening и закреплённые
окружения не меняются; код проекта исполняется только в прежнем контейнере.

Четыре новых модуля `project_checks` отделены от проектов и runner. Они не могут
импортировать команды, модели, сервисы или ключи; это закреплено import contract.
Статический и runner-отчёты хранятся в прежних репозиториях. Отдельный итог содержит
их ссылки и канонические SHA256; каждое чтение пересчитывает итог из составляющих,
проверяя проект, профиль, окружение, времена и хеши. Это защита от несогласованного
изменения локальных файлов, а не подпись или аттестация доверенного хоста.

Неполнота имеет приоритет над замечаниями и успехом: отсутствие статического
отчёта, partial, ошибка/неизвестность runner, неподтверждённая очистка или усечённый
вывод не превращаются в passed. При недоступном Docker статические результаты
сохраняются. При ошибке снимка/адаптера исполнение не начинается; сохраняется
неполный итог. Если runner не записал результат, состояние остаётся неизвестным,
без автоматического повтора и выдуманного подтверждения очистки.

Область проверки ограничена выбранным профилем. Копирование последовательное,
не атомарное для нескольких файлов; исходники не сохраняются в истории отдельным
архивом. AI не вызывается. Новый режим не заменяет исторические сводки UI10,
подписанный F06-аудит или будущую изоляцию пользователей при интернет-размещении.
