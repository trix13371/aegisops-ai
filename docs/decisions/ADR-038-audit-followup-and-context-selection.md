# ADR-038: исправления по аудиту и границы расширенного продукта

Статус: принято. 19 октября 2026.

Сверка Stage −1 на коммите 42868c7 выявила остановленную локальную БД,
пропуск ImportFrom aliases в карте, слабый охват больших папок и отсутствие
UI-набора в CI. См. [исторический аудит](../PLAN-AUDIT-2026-10-19.md).

## Контекст выбранного кода

`_python_meta` сохраняет кандидатов родительского модуля ImportFrom и добавляет
кандидатов подмодулей по `alias.name`. Относительный уровень считается от папки
импортирующего файла, level=1 оставляет её без подъёма. `alias.asname` — локальное
имя, отдельного пути не создаёт. Звёздочка не рассматривается как имя файла.
Обычный импорт символа сохраняет связь с модулем; предполагаемый путь подмодуля
принимается только при совпадении с известным путём карты. Это ограниченная
статическая эвристика, а не Python resolver или исполнение import.

Кандидаты уникальны, не более 20 путей, каждый до 128 символов. Слишком длинный
путь пропускается целиком: обрезка не должна создавать ложную ссылку на другой
файл. Анализируется прежний верхний уровень AST, динамические импорты и полная
семантика пакетной загрузки не добавляются.

Новый чистый `project_code.selection` содержит классификацию имени и
`choose_candidates`. Из одного и того же набора путей получается один порядок.
Casefold-дубликат получает лексикографически минимальное исходное написание.
Выбор чередует роли и папки внутри роли; у каждой папки собственный курсор.
В одной папке обычные модули идут перед `__init__.py`. Первые 80 мест отданы
коду, тестам и конфигурации, пока они доступны; затем добавляется документация.
Это распределение ограниченного контекста, а не доказательство важности файла.

Каталог больше не прекращает обход после первых 200 подходящих имён.
Сначала идёт ограниченный обход метаданных в ширину: до 4000 записей, глубина 12,
пятисекундный бюджет. Обнаруженные дочерние папки сортируются; src/lib/app/tests
имеют приоритет перед обычными именами, docs/assets — после них. Неограниченной
сортировки всего итератора директории нет. В результат выбираются до 200 путей,
вывод для интерфейса остаётся отсортированным по имени. При усечении — partial.

Карта применяет тот же распределённый выбор к 80 кандидатам. Guard/capture,
ограничения 12 КиБ на файл, 256 КиБ включённого в разбор текста, 5 файлов и
24 КиБ выбранного набора сохраняются. Ни каталог, ни selector не читают содержимое
для отправки модели. Подбор не создаёт claims/preview и не вызывает нейросеть.
После применения отметок пользователь отдельно создаёт и проверяет предпросмотр.

Детерминированность относится к одному набору обнаруженных путей. Прерывание по
таймеру/entry-limit, изменения папки и разный порядок ОС до усечения могут
изменить этот набор. Полного охвата больших репозиториев, обнаружения всех
связей и достаточности выбранного контекста не обещается. Причина «центральный
модуль» используется только при наличии входящих импортов в ограниченной карте;
запасные модули без этого признака называются дополнительными.

Если связанного теста нет, до заполнения запасными модулями пробуется один
доступный тестовый файл. Причина явно говорит о ручной проверке, не о связи
с точкой входа. Дополнительный Python/JS/TS-код имеет приоритет перед файлами
данных JSON/YAML/TOML с общей ролью module. Все добавления проходят тот же бюджет.

## Проверки и эксплуатация

GitHub Actions дополнен закреплённым setup-node v4.4.0 и Node 22:
`node --check` продукта, затем `node --test tests/ui/dashboard-flow.test.cjs`.
Источник закреплённого action:
[официальный релиз](https://github.com/actions/setup-node/releases/tag/v4.4.0).
Существующие Python/PostgreSQL/OPA/kind проверки не удаляются. Добавление шага
не является подтверждением его выполнения на GitHub до отдельного push/run.

Остановленный PostgreSQL запущен из существующего контейнера и volume.
Для живой проверки kind штатно обновлён read-only token с прежним TTL/правами.
Автозапуск БД из веб-интерфейса, автоматическое продление токена и изменение
kill switch не добавляются. Инфраструктурная готовность остаётся отдельной
от результата локальной статической проверки проекта.

## Три разных границы продукта

1. Kubernetes-ядро S0/F: локальная учебная среда, каталог, policy и описательный
   dry-run, L0. Изменений Kubernetes по рекомендации модели нет.
2. Проверка пользовательских проектов: локальный реестр/снимки, статический
   анализ без запуска; отдельные Docker-профили выполняют код после согласия
   ([ADR-023](ADR-023-isolated-python-checks.md),
   [ADR-027](ADR-027-isolated-javascript-checks.md)). Выбранный код уходит внешней
   модели только после предпросмотра и согласия
   ([ADR-033](ADR-033-selected-code-review.md)).
3. Будущий серверный продукт: права владельцев, серверные источники проектов,
   отдельный исполнитель, очередь/хранилище и приёмка изоляции пока относятся
   к [W01…W05](../internet-deployment-roadmap.md). Публикация отложена пользователем.

Это уточнение области ранних ADR-003/threat model, а не разрешение production
данных Kubernetes, автоматического исправления, L2 или общедоступного исполнения.
