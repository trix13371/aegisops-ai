# ADR-008 — описание действия и транзакционный аудит

Принято: 15 октября 2026. Локальный прототип S0-07, B.6/8/13/14.

PolicyChecker использует default-deny и четыре явные ветви каталога. L0
допускает описание R1/R2; исполнительных полномочий не возникает. Namespace,
параметры, целевой workload, класс обратимости и ID проверяются повторно.
Rollback требует однозначного Deployment; ReplicaSet не переименовывается.
Содержание логов не распознаётся как язык команд или вход политики.

PolicyDecision получает необязательный input_hash для совместимости чтения
ранних DTO. Текущие решения всегда содержат SHA-256 канонических Incident,
Recommendation, каталога и версии политики. DryRunEngine требует точного
равенства с пересчитанным решением. Это исключает использование разрешения
после изменения предложения с сохранённым recommendation_id. Хеш не подписан
и не защищает от изменения приложения владельцем хоста.

Dry-run — шаблонное описание, без проверки эффекта, текущего существования
workload, lease/rate-limit или успешности отката. Все реальные capabilities
заблокированы. Свободные title/rationale/explanation не становятся summary.

AuditStore имеет только append и lifecycle close. Валидированный и очищенный
AuditRecord вместе с индексируемыми полями записывается одной транзакцией.
Контекст пересобирается из incident, политика/summary пересчитываются;
изменённые хеши, цитаты и вердикты отвергаются. Повтор UUID — ошибка INSERT,
не UPDATE и не молчаливый успех. Ограничение записи — 512 KiB.

Роль приложения/миграция проверяются перед работой; разрешены INSERT/SELECT,
запрещены UPDATE/DELETE/TRUNCATE/DDL. SQL echo отключён, параметры скрыты.
Ошибка записи прерывает CLI до вывода completed. Обычные failed/blocked
сохраняются без dry-run; ранний environment block может не иметь incident,
но обязан иметь причину. Полезные валидные evidence сохраняются и при ошибке
поздней стадии. Непроверяемый/испорченный record не записывается как достоверный.

JSONB и колонки начальной миграции достаточны. Hash-chain, подпись и WORM
не добавляются. Администратор БД по-прежнему может менять записи. Этот аудит
не даёт production-гарантий. ReviewService работает с одним обнаруженным
инцидентом; полный source pipeline и eval остаются S0-08.
