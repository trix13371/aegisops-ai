# ADR-018: локальная подписанная передача collector → Control Plane

Принято 15 октября 2026. F09, следующий локальный срез Foundation & Safety.
Задача — отделить чтение Kubernetes от анализа, политик и аудита. Транспорт
первого среза — файлы на одном доверенном хосте; сетевой протокол не добавляется.

`aegisops-collector collect` и `aegisops-control consume UUID` — разные процессы.
Общий BatchProcessor вынесен из прежнего Pipeline без импорта sources/SDK.
15 import-контрактов включают новые запреты: collector не зависит от LLM/OPA/DB,
Control Plane и ядро обработки не зависят от collector/SDK. Их точки входа
удаляют переменные другой роли; DB-wrapper фильтрует environment до запуска
Control Plane, не передавая owner/migration/API/kube настройки. Это не sandbox.

Операторский enrollment закрепляет публичный Ed25519-ключ и UUID регистрации
только нашего kind. Закрытый ключ независим от F06/F07/API, находится вне Git
под ACL текущего Windows SID или POSIX 0600. Это native PEM, без шифрования.
Повторный init запрещён; автоматического сброса, ротации и повторной регистрации
при пересоздании кластера нет.

Сборщик закрывает read-only session, санитизирует DTO и подписывает канонический
JSON с отдельным domain prefix. Envelope связывает UUID, identity, регистрацию,
cluster, key ID, origin, класс данных и timestamps с содержимым. Допустимы только
local_kind/internal, ≤200 уникальных snapshots, ≤1 MiB и lifetime ≤5 минут.
Наблюдения должны быть не старше пяти минут к issued_at и не из будущего.
Control Plane проверяет публичную подпись и все связи, включая факт применения
текущего sanitizer; duplicate JSON keys, неверный UUID файла и символические
компоненты пути отвергаются. Класс данных нельзя понизить содержимым пакета.

До анализа создаётся exclusive claim с fsync файла. Он остаётся после любого
неопределённого исхода. Завершённая квитанция создаётся только после обработки
всех инцидентов и полного совпадения прочитанного аудита с новыми записями.
Один инцидент — одна транзакция аудита; атомарной транзакции всего батча нет.
Ошибка первой/частичной записи или повреждённая квитанция не приводят к retry.
Конкурирующий потребитель получает отказ на claim, не запускает второй анализ.

Повтор готовой квитанции проверяет подпись/хеш пакета, provenance и согласованность
с текущими строками аудита. Он возвращает прежние run IDs без новой модели,
политики и записи, даже после expiry. Это чтение истории, не возобновление работы.
Claim/receipt сами не подписаны и не входят в F06 snapshot; связанный telemetry
provenance внутри audit JSONB защищается следующим ручным checkpoint F06.
Старый AuditRecord без telemetry читается как прежде; raw история не мигрируется.

В этом CLI используется только offline fallback для internal. Обязательны
DryRunPEP, подписанный policy release, mTLS OPA и append-only DB роль.
Нет настройки обхода через Python policy mode или OpenRouter; прежние CLI
команды сохраняют свои ранее определённые возможности.

Ограничения: доверены host/user, операторский trust, часы и файловая система.
Тот же OS-пользователь может прочитать чужой ключ или изменить spool. Проверка
путей не защищает от враждебной гонки владельца файловой системы. Redaction не
гарантирует обнаружение всех секретов; очищенный пакет остаётся internal.
Нет защиты от отката всего состояния, power-loss durability каталога, очереди,
удалённой identity/аттестации, автоматического reconcile, gRPC/mTLS collector,
HA, exactly-once исполнения или исполнителя. Разделение OS identity и процедура
восстановления неопределённых попыток остаются отдельными работами.
