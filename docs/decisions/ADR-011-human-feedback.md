# ADR-011 — оценка рекомендаций человеком

Принято: 15 октября 2026. F02, пункт 4.5 плана до MVP: минимальный CLI
для обратной связи. Foundation & Safety продолжается; уровень остаётся L0.

Оценка относится к сохранённому run_id с рекомендацией и её каноническому
SHA-256. Без рекомендации, при неизвестном UUID или несовпадении привязки
запись отвергается. Значения: useful, incorrect, unsafe, uncertain. Это
мнение пользователя, а не фактический исход инцидента или эталонный диагноз.

Reviewer — локальный псевдоним, не аутентифицированная SRE identity.
Комментарий ограничен и очищается до INSERT/вывода; эвристика не гарантирует
удаление всех PII и секретов. Модель не получает оценки и не имеет инструментов
их записи. Оценка не одобряет действие, не повышает уровень и не меняет policy.

Отдельная таблица recommendation_feedback допускает SELECT/INSERT приложению,
без UPDATE/DELETE/TRUNCATE/DDL. Миграция добавляет таблицу без изменения старых
audit_runs. Doctor проверяет обе таблицы, их владельцев и права.

История неизменяема для app-роли. Для первого отзыва на run+reviewer разрешён
один корень. Исправление — новая запись с явным supersedes_id текущего отзыва.
FK связывает родителя с тем же run/reviewer; уникальность parent запрещает
две конкурентные правки одного отзыва. Запрос со старым parent отказывает,
старое мнение сохраняется. Повторный INSERT того же UUID не создаёт дубликат.

Сводка считает только листья цепочек, отдельно для synthetic/local-kind,
с явным лимитом 1…100 и has_more. Несколько пользователей могут оценивать
одну рекомендацию: это число мнений, не число независимых инцидентов.
История и superseded-оценки в текущую сводку не входят. Отчёт не вычисляет
accuracy, доверительные интервалы или прохождение G0 на этих данных.

Команды: feedback add RUN_ID --reviewer ALIAS --assessment VALUE
[--comment TEXT] [--supersedes UUID]; feedback list [--run-id UUID] --limit N;
feedback summary --source synthetic|local-kind --limit N. Вывод add появляется
только после COMMIT. Ошибки соединения/валидации нормализованы, raw SQL и
credentials не выводятся. Комментарии с секретами нельзя вводить в shell history.

Обычная PostgreSQL и доверенный владелец хоста остаются прежней границей:
нет WORM, подписи, независимой identity, доказательства авторства или Shadow.
