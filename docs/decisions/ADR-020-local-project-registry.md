# ADR-020: локальные проекты и ограниченная статическая проверка

Завершено 16 октября 2026. UI02 расширяет локальную панель регистрацией папок.
Существующие incident-контракты local_kind/synthetic не переиспользуются для
исходников: новые отчёты имеют отдельный профиль `aegisops-local-static-v1`.

Пользователь явно задаёт имя и абсолютный путь. До чтения проекта отвергаются
URL/UNC, относительные пути, символические ссылки/junction, диск и home целиком.
В приватный реестр записываются UUID, имя, путь, время и filesystem device/inode.
Ключ identity папки проверяется при сканировании; подмена самой папки требует
повторной регистрации. Один путь нельзя добавить дважды, максимум 50 проектов.

`aegisops.projects` содержит файловый репозиторий, frozen DTO и scanner без
импорта SDK, моделей, DB/config, сетевого транспорта или subprocess. Это отдельный
17-й import-контракт. Проект не добавляется в sys.path, его инструменты, тесты,
хуки и package scripts никогда не исполняются. Статический job использует ту же
блокировку одиночного запуска и тот же Host/Origin/session контроль панели.
Доступ к folder API означает чтение выбранного пользователем локального пути;
внешней передачи или новой модели нет.

Профиль: ast.parse для Python; strict JSON с duplicate-key/constant rejection;
UTF-8 YAML/TOML; SafeLoader без alias expansion с ограничением токенов/документов.
Из конфигурации извлекаются только признаки нескольких контейнерных настроек,
не полный schema validation. JS/TS учитываются как стек, без синтаксического
проверяющего инструмента. Значения source/config не копируются в отчёт.

Обход не следует ссылкам, пропускает типичные credentials, VCS, зависимости и
служебные папки. Это эвристический список исключений, не классификатор секретов.
Лимиты: 1000 файлов, 4000 entries, глубина 12, 256 KiB/файл, 8 MiB суммарно,
20 секунд между операциями, до 200 findings. Нет поддержанных файлов, aliases,
лимит или ошибка чтения дают partial. Синтаксическая ошибка — замечание, не
авария всего job. Исходные parser exceptions не передаются UI.

Реестр обновляется через fsynced временный файл/replace под lock одного host.
Отчёты пишутся exclusive, проверяются readback и только потом добавляются в
реестр. Ошибка индекса оставляет непривязанный файл, без автоматического retry.
Хранятся ссылки на 20 последних отчётов каждого проекта; файлы прежних отчётов
не удаляются автоматически. Удаление регистрации не затрагивает исходники или
отчёты. Повреждённое состояние приводит к отказу, а не к пустому новому реестру.

Ограничения: trusted host/user/filesystem, не межпроцессный распределённый lock,
не защита от враждебных файловых гонок или потери питания. Бюджет времени не
прерывает системный вызов/парсер посреди операции. Отчёты имеют проверку структуры
и согласованности, но не криптографическую подпись; они не входят в F06 checkpoint.
Source snapshot/hash не фиксируется, результат относится к прочитанным данным
в момент запуска, а не к неизменяемой Git revision. Это не SAST, quality gate,
полное тестирование, допуск production или подключение произвольного кластера.
Дальнейший запуск тестов требует отдельного изолированного runner и политики.
