# ADR-012 — сравнение диагноза с размеченным исходом

Принято: 15 октября 2026. F03: следующий локальный срез eval, п. 4.6 плана до MVP.
Фактических постмортемов/SRE-оценок пока нет: добавляется механизм сравнения,
проверяемый учебными случаями. Это не Shadow и не прохождение G0.

FeedbackRecord получает необязательные confirmed_cause, incident_outcome
(resolved/unresolved/unknown) и reference (ограниченный ID постмортема/тикета).
Для причины или исхода обязательна reference; unknown не считается
подтверждённой причиной. Это утверждение локального reviewer со ссылкой,
не проверенное авторство/содержимое источника. Внешние ссылки не открываются.
Миграция 0003 добавляет nullable-колонки, прежние отзывы остаются валидными.
Исправление по-прежнему заменяет весь отзыв новой записью; пропущенные поля
не наследуются автоматически. Модели не получают разметку.

feedback quality сравнивает актуальные отзывы с сохранёнными диагнозами,
отдельно по origin, максимум 100 отзывов. Группировка по incident_id исключает
повторный подсчёт запусков и reviewer одного инцидента. Берётся самый поздний
оценённый запуск по started_at/UUID; результаты разных моделей не смешиваются
скрытно: каждый case содержит prediction_kind, provider и model_name.
ID детектора включает пятиминутное окно: такие группы ещё не являются
независимыми постмортемами или полным жизненным циклом инцидента.

Все текущие ненулевые причины/известные исходы группы должны согласоваться.
Противоречие — conflict, без match/mismatch. Отсутствие причины — unlabelled.
Одна конкретная категория диагноза сравнивается с разметкой; unknown/несколько
категорий — abstained. Отказ модели, fake и настоящий ответ обозначаются
отдельно; совпадение fallback не считается подтверждением качества модели.
Resolved означает записанный пользователем исход, а не эффект рекомендации.

Чтение выполняется в одном read-only REPEATABLE READ snapshot. Ограничение
числа отзывов может разрезать группу: отдельный ограниченный запрос обнаруживает
не вошедшие текущие отзывы тех же incident_id. Такая группа sample_incomplete
и не сравнивается. has_more остаётся явным; отчёт не делает выводов о всей БД.
Привязка отзыва к origin/ID/hash рекомендации повторно проверяется при чтении.

Отчёт показывает абсолютные количества и ссылки на audit/feedback UUID,
не вычисляет accuracy, доверительные интервалы, MTTR или gate. В разработческой
БД есть автоматические тестовые labels, не реальные оценки SRE. Ручная разметка
не меняет policy, уровень L0, исходный аудит и не запускает действия.
