# ADR-040: безопасная диагностика сбоев синтетической оценки

Статус: принято. Дата: 19 октября 2026. Шаг UI24.

## Контекст

Первый разрешённый прогон v2 завершился на первой попытке, без принятых ответов,
через приблизительно 31.5 секунды. Транспорт ограничен 30 секундами, но старый
код сводил все причины к общему исключению. Тайм-аут правдоподобен, но не доказан.
Сравнение качества модели и улучшение её инструкций по ответам пока невозможны.

## Решение

Добавить к AnalysisError закрытый безопасный code, сохранив прежнее общее сообщение.
Разрешены unavailable, timeout, network, http_error, invalid_response, invalid_review.
Неизвестная строка и нестроковый аргумент заменяются на unavailable. Сырые тексты
исключений, ключи, HTTP-ответы, адреса и данные провайдера не сохраняются.

Маршрут OpenRouter различает socket/deadline timeout, сетевую ошибку до дедлайна,
неуспешный HTTP-статус и некорректный ответ. Вызванный таймером OSError после
дедлайна классифицируется как timeout. JSON, модель, finish reason, инструменты,
лимиты тела и usage по-прежнему проверяются. Wrapper разбора сохраняет безопасный
код транспорта; ошибка валидации CodeReview становится invalid_review.
Прямые провайдеры могут оставаться unavailable: не обещаем классификацию, которую
их существующий транспорт не передаёт.

EvalResultV2 получает необязательное failure с закрытым code и необязательным
идентификатором из существующих примеров. Завершённый результат не может иметь
failure. Старые записи без поля читаются с None; v1 DTO не меняется. Worker
фиксирует текущий пример до вызова и сохраняет диагностику вместе с уже принятыми
ответами. Даже неизвестный изменённый code не переносится в результат.

UI использует собственный закрытый словарь русских подписей и текстовые DOM-узлы.
Для старого failed без диагностики показывается «Причина сбоя не была сохранена».
Расход подписан как токены принятых ответов; неуспешная попытка тоже могла быть
платной, её расход неизвестен. Не дописываем причину в старую запись по догадке.

Не меняются таймер 30 секунд, TLS/proxy, фиксированные endpoint/model,
лимит девяти запросов, привязка провайдера, O_EXCL, запрет retry, профиль набора,
хеш, эталоны и формула оценки. Нового платного прогона после изменения нет.

## Проверки и ограничения

Сокет, HTTPS и таймер в тестах подменены. Проверены ранний и поздний OSError,
тайм-ауты подключения/ответа/чтения, HTTP и malformed response, очистка ресурсов,
отсутствие повторов и утечки канарейки, строгий DTO, частичные ответы worker
и представление ошибок. Код причины — диагностическая категория, а не сырой
статус сервиса. Она помогает следующему разрешённому запуску, но не восстанавливает
причину первого прогона и не измеряет качество модели.
