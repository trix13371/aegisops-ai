# ADR-025: сравнение сохранённых результатов

16 октября 2026. Продолжаем локальный функционал; подготовка размещения отложена
согласно уточнению пользователя. Следующая функция показывает изменения между
двумя сохранёнными проверками одного зарегистрированного проекта.

Статический compare_reports — чистая функция без IO. Входные DTO повторно
валидируются; одинаковый UUID и разные project_id отвергаются. Сопоставимость
требует одинаковой rules_version и двух отчётов с partial=false. Иначе возвращаются
причина и общие количества, без added/removed/unchanged и выводов об исправлении.

Замечания сопоставляются как multiset по file/code/severity/location/line.
Сообщение/рекомендация не являются identity. Дубликаты учитываются по количеству,
сохранённые Finding остаются неизменными. Added берутся из нового отчёта, removed
из исходного. Это разница наблюдений, не diff кода или доказательство исправления;
rename, удаление/исключение файла, смещение строки могут менять identity.
Статический scanner по-прежнему не фиксирует immutable source revision.

Отдельный compare_runs сопоставляет статусы Ruff/pytest, без разбора raw output
или оценки количества исправленных тестов. Требуются правильная связь claim/result,
два checks_completed с подтверждённым удалением контейнеров, snapshot/image ID,
оба инструмента и отсутствие output_truncated. Разные image ID, pending и
неподтверждённая область запрещают автоматическое сравнение. Переходы обозначают
буквально наблюдаемый статус: unchanged, now_passed, no_longer_passed, changed.
Совпадение snapshot SHA256 показано отдельно: тесты могут дать разные результаты
на одном снимке, честность исполнения внутри контейнера не аттестована (ADR-023).

Новые GET /api/project-comparison/<base UUID>/<target UUID> и
/api/run-comparison/<base UUID>/<target UUID> используют прежние точные Host и
сессию; оба проекта должны быть зарегистрированы и совпадать. Неверные ID,
повреждённые файлы, одинаковый отчёт или разные проекты дают фиксированный отказ.
Запуск worker, source read и платный API не входят в эти операции. Модули
comparison остаются под существующими import-контрактами projects/project_runner.

UI предлагает выбор пары из последних 20 элементов истории, по умолчанию
предпоследний → последний. Один элемент нельзя выбрать с двух сторон. Для
одной проверки показано, что нужен второй результат. При смене правил/области
UI объясняет отказ от оценки. Ответы вставляются как textContent; select включён
в keyboard focus trap. Async sequence guard защищает от устаревшего ответа.

Сравнение вычисляется при чтении, не сохраняет дополнительный audit и не меняет
историю/источники. Нет новых зависимостей, миграций, ключей или общей очереди.
Текущий single-user/filesystem trust сохраняется; future owner authorization
не заменяется знанием UUID. Сравнение не quality gate и не гарантия корректности.
