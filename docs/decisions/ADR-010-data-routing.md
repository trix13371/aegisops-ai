# ADR-010 — классы данных и маршрутизация LLM

Принято: 15 октября 2026. Первый локальный срез Foundation & Safety (F01),
пункт 4.5 плана до MVP. S0-01…S0-08 завершены; эта работа не означает
завершение Этапа 0a или разрешение Shadow на реальных данных.

Переиспользуем DTO, collector, санитизацию, AnalysisEngine, PolicyChecker,
dry-run и PostgreSQL-аудит прототипа. Исполнителя по-прежнему нет, уровень L0.

Классификация задаётся доверенной конфигурацией приложения, а не моделью
или текстом телеметрии. Для учебных synthetic минимальный класс public,
для любого живого local-kind — internal. Явно можно повысить класс до
confidential/restricted; понижение ниже минимума происхождения отвергается.
Отсутствие явного значения использует этот минимум, неизвестные значения — отказ.

Версионируемая чистая политика local-data-v1 разрешает OpenRouter только
для public. Internal/confidential допускают лишь явно выбранную локальную
модель или offline fake. Restricted не передаётся никакой модели, включая
fake: остаются детерминированные резервные правила. Неизвестный провайдер
запрещён. Автоматической смены провайдера и внешнего fallback нет.

Класс привязан к LLMRequest и проверяется вместе с хешем запроса. Для
существующих запросов с неявным классом сохраняются прежние хеши и fixtures;
явное значение, равное минимуму, нормализуется к неявному. Более высокий
класс входит в хеш. Класс не добавляется в текст инструкций или наблюдений.

AnalysisEngine проверяет маршрут до расходования бюджета и вызова клиента.
При запрете записывает routing_denied, ноль вызовов и ноль зарезервированных
токенов, строит резервную рекомендацию. HTTP-адаптер повторяет проверку
перед созданием соединения; fake также проверяет маршрут при прямом вызове.
В parameters
LLMMetadata сохраняются класс, версия, разрешение и фиксированная причина.
Это дополнительная метаинформация в существующем JSONB, без миграции БД.

CLI analyze/review/run получает --data-class; eval остаётся offline и
фиксированным. До F01 внешнему API были допустимы оба происхождения;
теперь local-kind через OpenRouter даёт только резервный разбор без сети.

Это минимальная локальная граница передачи данных. Public относится только
к подготовленным учебным входам; произвольные реальные данные нельзя
объявлять synthetic. Нет production-классификатора, DLP/PII-гарантии,
zero-retention, проверки data residency, изоляции процесса или защиты от
владельца хоста. Loopback может быть туннелем. Restricted остаётся доступен
детерминированному коду и локальному аудиту: это запрет передачи модели,
не политика хранения. Условия G(−1) по реальным данным остаются открытыми.
