# ADR-034: контекст проекта и проверка предложений AI

Статус: принято. Дата: 17 октября 2026.

Пользователь запросил все пять улучшений: карту, подбор контекста, проверку
замечаний тестами, diff с тестом и небольшой контрольный набор качества.

Карта и подсказки остаются чистым локальным анализом. Используются прежние
ограниченные catalog/capture и фильтры путей/секретов, AST для Python и эвристики
для JS/TS. Дополнительные границы: 80 кандидатов, 256 КиБ текста, 5 секунд,
12 символов и 20 импортов/связей на файл, до 10 подсказок. Неполнота отмечается
явно. Это не полный граф вызовов, разрешение зависимостей или гарантия охвата.
Содержимое для карты читается локально; исходящий предпросмотр по-прежнему
ограничен пятью явно выбранными файлами и 24 КиБ суммарно.

Предложение исправления — отдельный профиль project-code-fix-v1 и отдельное
согласие. Точный общий builder формирует payload для UI и транспорта: выбранные
замороженные файлы, их относительные пути, язык, содержимое и одно сохранённое
замечание. Прежний профиль разбора без отдельных имён не меняется. Исправление
ограничено одним выбранным файлом, новым тестом и объяснением; проверяются схема,
язык, бюджет, признаки секретов и Python-синтаксис без исполнения на хосте.
Изменения возвращаются как diff, с маркерами отсутствия завершающего перевода
строки. Автоматического применения и записи в исходную папку нет.

LabRepository связывает claim/result с digest предпросмотра и сохранённого
разбора. Разрешена одна попытка предложения на предпросмотр, O_EXCL started,
повторное чтение доказательств до/после обращения. Worker получает прежний
отдельный runtime-ключ, фиксированные endpoint/model и лимит 2800 токенов.
Нет fallback, tools и автоматического повтора. Сбой сохраняет только закрытую
категорию ошибки; исходные сообщения провайдера и исключения не раскрываются.
Неизвестная внутренняя ошибка остаётся unknown, а не выдуманной причиной связи.

Проверка — ещё одно явное согласие project-code-verification-v1. Из frozen
preview и предложения формируются два детерминированных снимка с одинаковым
тестом. Применяются прежние Python/Node/Vitest окружения, фиксированные образы
и ограничения Docker. Живая папка не читается, ключ не передаётся исполнителю.
Верификация связывает фактические хеши снимков, разные ID запусков, проект,
окружение и время. Для reproduced нужны полные два прогона в контейнерах,
успешная проверка синтаксиса, тест до с exit 1, тест после с exit 0,
совпадающий образ и подтверждённая очистка. Неполные результаты, усечение,
недоступный исполнитель и сомнительные доказательства дают inconclusive.
Это проверка поведения конкретного сгенерированного теста, не семантическое
доказательство дефекта или безопасности исправления.

Оценка качества использует три версионируемых синтетических случая: ошибочная
граница цикла, корректное сложение и корректное сложение с инструкцией в
комментарии. Явное согласие разрешает до трёх последовательных платных запросов.
Хеш набора проверяется до/между/после вызовов. Счёт ведётся по категории и
пересечению строк с сопоставлением один к одному. Неполная серия не получает
итоговые precision/recall; отсутствие ответа не считается пропущенным дефектом.
История хранит последние 20 ссылок. Учебная разметка не заменяет реальный benchmark.

Маршруты сохраняют session/Host/Origin, no-store, CSP и общий job lock.
Чистые модели/карта/снимки/оценка отделены импортным контрактом от транспорта,
сервисов и исполнения. Windows launcher, DPAPI и Docker CLI остаются локальными
адаптерами. Публикация в интернете требует отдельной приёмки из существующего
плана размещения; эта работа не открывает сервис наружу.
