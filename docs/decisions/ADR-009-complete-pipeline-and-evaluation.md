# ADR-009 — полный конвейер, пустые результаты и честный eval

Принято: 15 октября 2026. S0-08, B.8/13/16/17.

Pipeline получает ObservationSource и ожидаемый origin из явного CLI-режима.
Сбор ограничен 200 снапшотами, весь список повторно валидируется, смешение
origin блокируется до анализа. LocalKindSource использует прежние credentials,
guards/collector и закрывает reader. Один AnalysisEngine/RunBudget обслуживает
все инциденты батча; ReviewService проверяет политику, описывает и сохраняет.
Origin по-прежнему метка, а фактический доступ контролируется источником/guards.

Без инцидентов нужно сохранить факт успешного наблюдения. Добавлен optional
NoIncidentObservation в AuditRecord: source, snapshot_count, detected_incidents=0.
Только completed без incident, анализа, LLM, policy, dry-run, context_hash и errors.
Completed с incident сохраняет все прежние требования. Это уточняет B.8 для
здорового/пустого источника, не создавая фиктивного диагноза или статуса blocked.
SQL-статусы, nullable incident_id и JSONB уже поддерживают это; миграции нет.
Старые корректные записи читаются без observation. Экспортированы новые схемы.

Ранние ошибки среды пишутся как blocked, технические ошибки входа/детекции —
failed. Выводит CLI только сохранённый результат, с exit 1 для blocked/failed.
AuditStoreError всегда прерывает дальнейшую обработку. Транзакции независимы
по записям: при позднем сбое уже записанные данные остаются, успешного итога
всей серии нет. UUID создаётся на запись; incident ID/hash остаются стабильны.

Reader имеет только ограниченные SELECT list/show. Show сверяет UUID запроса
с JSONB, валидирует, очищает и проверяет контекст. Старый вердикт отображается,
не воспроизводится текущей политикой. При append current-policy сверка остаётся
обязательной. Это чтение истории, не подтверждение подлинности записи.

Eval строго offline: fake-v1, фиксированные десять expected.yaml, 10 запусков
того же Pipeline/AuditStore. Учитываются TP/FP/TN/FN, категории, действия,
canary/исполнение. Безопасный fake-ответ к инструкции в логе не должен быть
объявлен блокировкой атаки настоящей моделью. Поэтому метрика отказа политики
на этой фикстуре отделена от шести подмен структурированных предложений.
Эти probes проверяют policy, не генеративную устойчивость, и не пишут новые
сценарные записи. Не применяются Shadow/MVP пороги или статистические выводы.

Платные API в eval/CI не нужны. UI, executor, production, Shadow, подпись/WORM
не добавляются. Live-kind положительная приёмка текущей среды ожидает
исправления публикации Docker API-порта; ранний отказ проверен отдельно.
