# ADR-013 — версионируемые runbook как справочный контекст

Принято: 15 октября 2026. F04, runbook-каталог из п. 4.5 Foundation & Safety.
Уровень L0. Runbook помогают диагностике, не расширяют каталог действий.

Канонический каталог runbooks/catalog.yaml хранится в Git и копируется в wheel.
Документ имеет ID, semver, заголовок, сигнал и короткие русские шаги диагностики.
Нет загрузки URL, произвольных путей, embeddings, загрузок от пользователя или
исполнения команд. Изменения требуют обычного ревью Git; подписи и проверка
четырёх глаз программно пока не реализованы.
Этот срез допускает только явно public учебные документы. Internal и другие
классы runbook отвергаются: их объединение с классом телеметрии ещё не реализовано.
Метка public — утверждение автора, а не автоматическая классификация содержимого.

Индекс выбирает общий CrashLoop runbook и максимум один специальный: OOMKilled
только по структурированному статусу, иначе ненулевой exit code. Тексты логов,
Events, имя сценария и ожидания тестов не участвуют в выборе. Справочник не
подтверждает причину инцидента: нужны ссылки на настоящие observation evidence.

DTO ограничивают каталог тремя документами, документ — 1024 байт канонического
JSON, выборку из двух документов — 2048 байт. Дубликаты, неизвестные поля,
aliases/duplicate YAML keys, symlink/path escapes и secret-shaped содержимое
отвергаются до промпта. Превышение бюджета не увеличивает лимиты модели.
Тексты считаются недоверенными данными, даже если лежат в репозитории.

Новый prompt analysis-v2 содержит runbooks внутри UNTRUSTED_OBSERVATIONS_JSON,
отдельно от diagnosis_context. ID runbook не являются supporting_evidence_ids.
Хеш prompt включает весь справочный пакет; selection hash связывает версию
каталога и хеши документов. Проверяется также соответствие сигналов контексту.
В LLMMetadata.parameters добавляются ровно три поля: runbook_catalog_version,
runbook_selection_hash и runbook_refs (ID@version). Сохраняется предел 16 полей,
включая returned_model и два поля fallback из ReviewService.

Учебные ответы перевыпускаются как fixture-v2 под новые prompt hash; старые
assets analysis-v1 остаются для истории. Исторический аудит читается без
повторной проверки старого промпта по текущему каталогу. Выбранные документы
не обязательно были отправлены модели: это определяется calls_this_incident.
Схема БД не меняется. Границы передачи данных F01 и лимиты RunBudget сохраняются.

Новый CLI runbook list/show работает без сети/БД/ключа. Бесплатный eval по-прежнему
проверяет механику, а не качество настоящей модели. Нет гарантии защиты самой
модели от injection; полномочия ограничивают DTO, policy, отсутствие инструментов
и исполнителя. Hash — проверка целостности, не подпись или доказательство авторства.
