# UI14 — объяснение совместной проверки через OpenRouter

17 октября 2026. DeepSeek подготовил продуктовый код, Gemini — тесты и независимое
ревью через действующий адаптер OpenRouter. Оркестратор готовил ограниченные задачи,
проверял ответы, применял точные изменения, выполнял проверки и оформлял документацию.
Встроенные Codex-агенты для кода/тестов не использовались.

## Реализовано

В общем отчёте «Файлы + тесты» добавлены предпросмотр исходящей сводки, отдельное
согласие на один платный запрос и кнопка «Объяснить результаты». Сохраняются краткий
разбор, до пяти приоритетных действий, ручной следующий шаг и ограничения.
Статусы статической проверки и runner от ответа модели не меняются.

Новый закрытый профиль project-full-check-summary-v1 передаёт только коды, счётчики,
статусы, причины завершения и ограничения. Источники, пути, имена, логи, UUID, хеши,
времена и метаданные пакетов не передаются. Неполнота имеет приоритет. Сохраняются
различия общего захваченного ввода и фактического исполнения.

Один claim и started O_EXCL на сохранённый check_id. Worker повторно читает ссылки
и хеши до и после обращения. Неизвестная/неудачная попытка не переотправляется;
повторное открытие читает сохранённый ответ. Незавершённая основная проверка не
допускается к AI. Повреждение источников останавливает запрос или сохранение успеха.
Используются прежний отдельный runtime-ключ, его preflight и фиксированный transport:
1600 выходных токенов, без инструментов, fallback и автоматических повторов.
Режимы static/review, их DTO и старые хеши не менялись.

## Выполненные проверки

- Offline unit/contract/safety: **1290 passed, 3 skipped**,
  .local/ui14-offline.xml. Исключены integration, llm_live, kind_live, opa_live,
  runner_live. Внешние сервисы этот набор не проверяет.
- Целевые новые core/worker/HTTP тесты: **22 passed, 99 deselected**,
  .local/ui14-targeted.xml. Проверены закрытая проекция, отсутствие canary в
  исходящем JSON, allowed-codes, неполнота, pending, persisted/restart, O_EXCL,
  ошибки провайдера, изменение источников до/во время запроса, невозможность
  повторного вызова, session/Host, точный consent, mutex и фиксированные child args.
- Node UI tests: **21 passed**. Новые пять сценариев проверяют согласие и точный POST,
  блокировку после неопределённого ответа, сохранённые completed/pending/failed,
  вывод HTML-подобного текста через textContent, отсутствие AI для pending отчёта,
  отказ неизвестного профиля и отбрасывание позднего ответа старого окна.
- Ruff, format check изменённых Python-файлов, strict mypy **128** source files,
  **22 import contracts**, node --check и git diff --check прошли.
- PowerShell AST parser подтвердил синтаксис обновлённого wrapper без исполнения
  его credential/preflight/API-ветвей.
- Offline sdist и wheel в .local/ui14-dist; HTML/CSS/JS и четыре новых full_*.py
  модуля в wheel из sdist побайтово совпали с рабочими исходниками.
- Финальное независимое статическое ревью Gemini: accept, замечаний нет.

В браузере открыт прежний реальный отчёт Vitest, check_id
381a36e9-cf2b-42d5-9b12-7ed99df08b1b. Новый authenticated GET показал профиль,
not_requested и закрытую сводку. Предпросмотр содержит только заявленные поля.
Проверены состояния кнопки до/после отметки согласия; отметка затем снята.
Платная кнопка не нажималась. Сохранённый claim отсутствует: runtime API в этой
приёмке не вызывался. Провайдер успешного/ошибочного ответа подменялся в тестах.
Скриншот: .local/dashboard/screenshots/ui14-full-ai.png.

Некорректные тестовые заготовки Gemini с несуществующими API, неверным порядком
сохранения или неверными ожиданиями возвращались автору. Исправления не подменялись
ручным кодом оркестратора; форматирование выполнялось механически. Для одного
ограниченного ответа DeepSeek путь app.js сопоставлен с заранее разрешённым файлом;
неуникальная косметическая замена не применялась. Все применённые участки кода
взяты из завершённых ответов моделей. Материалы вне Git: work/agent-tasks/ui14.

Полнота live API не заявляется. Подтверждён локальный путь к транспортной границе
и его mock-ответы, а не новый оплаченный ответ OpenRouter. Кластерные действия,
политики, kill switch и F06-аудит в этой приёмке не изменялись.
